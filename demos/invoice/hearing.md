# ヒアリングシート（想定）

デモ用に、「よくある会社」を想定して埋めたもの。実際の案件では、お客様と一緒に埋める。
「（想定）」は、デモのために置いた仮の回答。お客様ごとに必ず確かめる。作りは、この想定に合わせている。

## 1. 会社と業務

| 項目 | 回答 |
|---|---|
| 業種・従業員数 | Web制作・デザインの会社（株式会社）、従業員5〜15名（想定）。請求先はすべて法人で、源泉徴収はない |
| 自動化したい業務（今の手順を順番に） | ①月末に、営業担当が今月の作業を経理に伝える → ②経理がExcelのひな形に取引先・品目・金額を手で打ち、PDFにして保存 → ③メールに添付して送る → ④翌月、ネットバンクの入金を見て、どの請求書の支払いかを一件ずつ照らし合わせ、Excelの一覧に「入金済み」と付ける |
| その業務にかかっている時間・頻度・件数 | 請求書は月30〜60枚（想定）。うち保守費など毎月同じ内容が15社前後。作成と送付で月末に丸1日、入金の照らし合わせで月に半日。保守費の出し忘れが年に数回ある |
| 自動化したあとの理想の状態 | 担当者が明細を入れ（取引先を選ぶと請求日・支払期限が入る）、経理がボタンを押せば、請求書のPDFとメールの下書きができる。毎月同じ請求は明細が自動で入る。入金は、銀行のCSVを置いてボタンを押せば、合うものは自動で「入金済み」になり、迷うものだけ人が見る |

## 2. 使う人と管理する人

| 項目 | 回答 |
|---|---|
| 毎日使う人（部署・人数・ITへの慣れ） | 各担当者（営業）3〜5名が、自分の作業を「明細」に入れる。経理の担当者1名が、請求書の作成と入金の取り込みをする（ユーザーに確認済み）。ITには詳しくない（想定） |
| 管理する人（設定の変更・トラブル対応をする人）はいるか | 総務・経理の責任者が兼任（想定）。専任のIT担当はいない |
| 担当者が替わる可能性（異動・引き継ぎ・パートなど） | あり。経理の担当者は引き継ぎがある |
| 使う端末（パソコン／スマートフォン） | パソコンのブラウザ |

## 3. 今の環境

| 項目 | 回答 |
|---|---|
| Google Workspace（会社のアカウント）か、個人のGoogleアカウントか | 個人のGoogleアカウント（想定）。ツールが送るメールは、自動の処理のエラーを管理者に知らせるものだけ。下書きは送信数に数えない |
| ツールを動かすアカウント（担当者が替わっても残る、会社のアカウント） | 経理の共用アカウント（想定）。メールの下書きは、ボタンを押した人のGmailにできる |
| すでに使っているフォルダ・シート・ファイルの形式 | 請求書のPDFを入れるフォルダと、ネットバンクのCSVを入れるフォルダは、会社が今使っているものを設定で指定する（作らない） |
| 一緒に使っている他のツール（会計ソフト・チャット・メールなど） | Gmail、ネットバンク（想定）。会計ソフトへの取り込みは、今回は扱わない |
| 他のツールに取り込むときに必要な項目 | 銀行のCSVを読む。銀行ごとに列の名前が違うので、「入金日」「振込名義」「入金額」の列の名前を設定で選べるようにする（ユーザーに確認済み）。CSVの文字コードは、日本の銀行に多い Shift_JIS と UTF-8 の両方を読む |

## 4. 会社の決まり（作り方が変わるところ）

| 項目 | 回答 |
|---|---|
| 業務の決まり（例：勘定科目の一覧、取引先ごとの扱い、承認の流れ） | 請求書は適格請求書（インボイス）。登録番号と、税率ごとの合計・消費税を載せる。単価は税抜で入れる。消費税は、税率ごとに合計してから1回だけ計算し、端数は切り捨て（ユーザーに確認済み。設定で四捨五入・切り上げにも変えられる）。承認の流れはない |
| 支払期限の決め方 | 取引先ごとに、締め日と支払日（例：月末締め翌月末払い）を登録し、請求日から自動で決める（ユーザーに確認済み）。契約ごとに期限が違うことがある（着手金・検収後30日など）ので、明細の支払期限は、取引先の条件で自動で入れたうえで書き換えられるようにする（ユーザーに確認済み）。支払日が土日祝でも、ずらさない（想定。お客様に確かめる） |
| 請求書番号の付け方 | 「請求日の年月-その月の通し番号」（例：2026-10-001）（ユーザーに確認済み）。取消した番号は使い回さない |
| 請求書を直すとき | 元の請求書を「取消」にして理由を残し、新しい番号で作り直す（ユーザーに確認済み）。元のPDFは消さず、ファイル名に「取消」と付ける |
| 毎月同じ内容の請求 | 「毎月の請求」シートに品目・金額を書いておくと、毎月1日に、その月の締め日を請求日にした明細が自動で入る（ユーザーに確認済み）。請求書を作るのは人がボタンで行う |
| 請求日の決め方 | 担当者が取引先を選ぶと、次に来る締め日を請求日として自動で入れる。すぐ請求する案件などは書き換えられる（ユーザーに確認済み） |
| 請求漏れの知らせ方 | 知らせない（ユーザーに確認済み）。請求書は経理が作り、誰がメールを送るかも会社ごとに違うため。担当者の伝え忘れのリマインドは、チャットで行う想定で、今回のスコープ外 |
| 入金の照らし合わせ | 振込名義と金額で請求書を探す。名義・金額が合えば自動で「入金済み」。2枚分をまとめた入金も、金額の合計が合えば自動。振込手数料ぶん少ない入金（差が880円以内）は、候補を出して黄色で確認に回す（ユーザーに確認済み。上限は設定で変えられる） |
| 決算月（年度の始まり） | 使わない（集計はしない） |
| データの名前の付け方・保存場所の決まり | PDFのファイル名は「請求書_番号_取引先名.pdf」（想定） |
| 例外になるケースと、その扱い | 取引先が登録されていない・金額が数字でない明細は、赤い行で残し、その取引先・請求日の請求書は作らない（ほかの請求書は作る）。メールアドレスがない取引先は、下書きを作らずに一覧で知らせる。請求書の支払いでない入金（利息など）は、黄色で「合う請求書がありません」と出し、そのままでよい |
